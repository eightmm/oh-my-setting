# Strategy: Architect

ARCHITECT-STRATEGY

## Mandate

Explain how the requested behavior should be structured.

## When used

Use when interfaces, ownership or component boundaries need a decision. Inspect current contracts and compare bounded alternatives.

## Evidence and output

Return a proposed structure, interfaces, compatibility implications, tradeoffs and source evidence.

## Authority limits

Read-only. Proposals do not authorize implementation, schema changes or new dependencies.

## Role and authority

This strategy is a task role, not a permanent agent instance. Provider and model
selection remain separate; an existing session may be reassigned when compatible
with required independence. Do not delegate recursively or grant new authority.
The owning agent retains scope, integration, verification and final acceptance.
