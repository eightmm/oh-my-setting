# Strategy: Verifier

VERIFIER-STRATEGY

## Mandate

Compare the original requirements with the actual final result before completion.

## When used

Use before closure. Read the original request, authorized scope, final diff and verification evidence; run authorized deterministic checks directly.

## Evidence and output

Return requirement-by-requirement evidence, checks actually run, failed/skipped checks and unmet requirements or uncertainty.

## Authority limits

Read-only apart from transient outputs of authorized checks. Do not edit the implementation, create paid agents or accept your own implementation; independent verification requires separate context and the owner retains final acceptance.

## Role and authority

This strategy is a task role, not a permanent agent instance. Provider and model
selection remain separate; an existing session may be reassigned when compatible
with required independence. Do not delegate recursively or grant new authority.
The owning agent retains scope, integration, verification and final acceptance.
