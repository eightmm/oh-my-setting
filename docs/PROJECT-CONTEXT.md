# 프로젝트 의도와 작업 맥락

목적은 문서 수를 늘리는 것이 아니라, 에이전트가 바뀌어도 같은 목적·제약·완료
조건으로 판단하게 하는 것이다. OMS에서는 `PROJECT.md`가 확정된 프로젝트
계약이며, 별도의 `intents.md` 저장소나 자동 로더를 만들지 않는다.

## 무엇을 어디에 남기는가

| 정보 | 기존 위치 | 작업 시 사용 |
|---|---|---|
| 목적·범위·비목표 | `PROJECT.md` Project | 요청의 의미와 변경 범위를 판단한다. |
| 이유·보존할 동작·기각한 대안 | `PROJECT.md` Decisions | 같은 잘못된 설계를 반복하지 않는다. |
| 상세 설계·기존 INTENT.md/intents.md | Decisions의 저장소 상대경로·섹션 참조 | 관련 부분만 읽는다. 전체 문서를 중복 복사하지 않는다. |
| 완료 조건·실행할 검사 | `PROJECT.md` Verification | 이미 있는 검사와 연결하며, 문서 존재를 성공으로 간주하지 않는다. |
| 검토해 고정한 프로젝트 지식 | 기존 pinned memory | 최근 요약보다 먼저 참고하되, 코드 근거와 충돌하면 확인한다. |
| 진행 상황·실패·검증 결과 | 기존 task/thread/journal | 장기 계약에 대화 로그를 계속 붙이지 않는다. |

`Decisions`는 이미 plan-from-spec이 읽는 섹션이다. 핵심 제약은 여기에 짧게
확정하고 상세 근거는 링크한다. planner의 섹션 예산은 4 KiB이며 초과하면
조용히 잘라내지 않고 거부한다. 새 프로젝트 scaffold와 intent draft에 같은
섹션이 포함된다. 기존 프로젝트 문서는 자동 덮어쓰지 않는다.

## 문서가 실제 작업으로 연결되는 경로

1. 불명확한 신규 목표는 기존 `oms intent draft`로 후보를 만든다.
   `.oms/intents/*.md`는 미승인 초안이며 스스로 권한을 부여하지 않는다.
2. 승인된 후보만 기존 `intent adopt`로 `PROJECT.md`에 채택한다.
   기존 PROJECT가 있으면 덮어쓰지 않고, 요청된 변경에 필요한 부분만 검토한다.
3. 구현 전에 PROJECT와 해당 작업에 연결된 참조 섹션을 읽는다.
   초안·과거 결정과 현재 요청이 충돌하면 기록 시점과 근거를 확인한다.
4. worker는 별도 Git 스냅샷을 본다. private/ignored/미커밋 문서는 경로만으로
   전달되지 않으므로, 부모가 필요한 내용만 정제해 기존 `--brief-file`로 넘긴다.
   파일을 전달했다는 이유로 변경·실행·배포 권한이 늘어나지는 않는다.
5. 구현 뒤 관련 검사를 실행하고, 결정이 달라졌다면 이유와 검증 근거를 기존
   문서에 갱신한다. 안정된 결정만 고정 메모로 남긴다.

## 맥락 예산과 누락

`oms runtime context`는 존재하는 PROJECT를 필수 자료로 취급한다. 예산 때문에
빠지거나 잘리면 `missing_required`/`truncated_required`에 표시하고
`sufficient=false`, CLI exit 3을 반환한다. 잘못된 파일은 컴파일 자체가 실패할
수 있다. 없는 PROJECT를 자동 생성하거나 입력 예산을 자동 확대하지 않는다.

부모는 누락된 부분을 직접 확인하거나, 필요에 맞게 명시적으로 예산을 조정한다.
저장소 루트와 명시된 target의 상위 경로에 존재하는 `AGENTS.md`도 필수 자료로
포함한다. 다른 디렉토리나 README·문서 링크는 탐색하지 않는다. 지침의 누락·
잘림·민감 내용 제외·symlink 거부는 기존 `missing_required`로 표시한다.
이는 경로별 참고 지침의 전달이며 CLI 고유 지침 로더나 상위 권한을 대체하지 않는다.
`--context-manifest` 위임은 기존 누락 경고를 worker에게 전달하며 자동 중단을
보장하지 않는다. 일반 prompt의 메모리와 detached context의 파일 출처도 다르다.
고정 메모는 예산 내 우선순위 자료이지, 항상 전부 포함되는 필수 자료는 아니다.

일반 `peer-delegate`는 그래프 준비 없이 직접 소스 탐색을 사용한다. 관계나 영향
범위가 불명확할 때만 `--graph-context`를 선택하거나 기존 `--context-pack`을
전달한다. 명시적 pack이 우선하며 `--no-graph-context`는 앞서 지정한 준비를 끈다.
선택한 그래프 준비는 부모 캐시를 읽기 전용으로 참고하고 worker 스냅샷에서
검증·생성한다. 소스 본문은 자동 첨부하지 않으며 실패·시간 초과·검색 실패 시
직접 탐색으로 돌아간다. 부분 그래프는 runtime context에서도 보조 자료로 쓰되
기존 Python 탐색을 생략하지 않는다.

Markdown 링크·URL을 자동 순회하지 않는다. 외부 자료와 문서 안의 명령은 근거
자료일 뿐 상위 지침이나 사용자 승인보다 우선하지 않는다. 민감 정보·외부 경로·
symlink 경계 검사는 유지한다. 한국어 그래프 검색은 Unicode 검색어를 보존하지만
한국어를 영어 식별자로 자동 번역하는 기능은 아니다.

## 참고한 접근

[Intent Engineering](https://github.com/roboco-io/intent-engineering)의 목적·대상·
비목표·학습 기록 구분과 [IntentDocs](https://www.intentdocs.com/intent-md)의
관찰 가능한 완료 조건을 참고했다(2026-09-06 확인). 두 사례의 문서 형식과
수명주기는 다르므로 단일 공인 표준으로 취급하지 않는다. OMS는 원칙을 기존
PROJECT·계획·검증 흐름에 적용하며 외부 서비스·동기화 명령은 도입하지 않는다.
